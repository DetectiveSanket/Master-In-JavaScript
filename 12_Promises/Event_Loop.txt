================================================================================
                    THE EVENT LOOP: JavaScript's Brain
================================================================================

📌 INTRODUCTION
---------------
Since you want to start from the ground up, let's look at the "Brain" of 
JavaScript.

To understand why we need Promises and Async/Await, you first need to 
understand the Event Loop. This is the secret sauce that allows JavaScript 
to be "fast" even though it can only do one thing at a time.



================================================================================
              1. THE GROUND REALITY: JavaScript is Single-Threaded
================================================================================

👨‍🍳 The Kitchen Analogy:
------------------------
Imagine a tiny kitchen with only one Chef (the JavaScript Engine).

   ✅ Quick Task:
      If a customer orders a "Quick Salad," the Chef makes it instantly.

   ❌ Slow Task (The Problem):
      If a customer orders "Slow Roasted Chicken" (which takes 4 hours), 
      and the Chef stands there staring at the oven, the whole restaurant 
      stops. No one else gets fed. This is called BLOCKING.

💡 The Solution:
   JavaScript avoids this by using the Event Loop.



================================================================================
                    2. THE THREE PARTS OF THE ENGINE
================================================================================

To manage tasks, JavaScript uses three main areas:


   🔹 THE CALL STACK (The Chef's To-Do List)
   ------------------------------------------
   • This is where code currently being executed lives
   • It's "Last In, First Out" (LIFO)


   🔹 THE WEB APIs (The Kitchen Assistants)
   ----------------------------------------
   • When you have a slow task (like fetching data or a timer), the Chef 
     hands it off to an assistant
   • The Chef doesn't wait; they move to the next order in the Stack


   🔹 THE CALLBACK QUEUE (The "Ready to Serve" Counter)
   ----------------------------------------------------
   • Once an assistant finishes a task, they put the result here
   • Waiting to be picked up by the Event Loop



================================================================================
                  3. HOW THE EVENT LOOP WORKS (The Cycle)
================================================================================

🔄 The Simple Job:
------------------
The Event Loop has one simple job: It looks at the Call Stack and the 
Callback Queue.

   RULE: 
   If the Call Stack is empty, it takes the first task from the Queue and 
   pushes it onto the Stack to be executed.



🔹 REAL-TIME EXAMPLE: The setTimeout Mystery
--------------------------------------------
Look at this code. What do you think prints first?

   📝 Code Example:
   
        console.log("1. Start");

        setTimeout(() => {
            console.log("2. Timer Finished");
        }, 0); // 0 milliseconds!

        console.log("3. End");


   📤 The Result: 
      1. Start 
      2. End 
      3. Timer Finished


   ❓ Why?
      Even though the timer was 0ms, JavaScript handed it to the 
      "Assistant" (Web API). The Chef immediately moved to "End." 
      Only after the Stack was empty did the Event Loop move 
      "Timer Finished" back to the Chef.



================================================================================
                4. LET'S BUILD: A Simple Weather Fetcher
================================================================================

Now that you know how the background works, let's use Async/Await to do 
something real: Getting weather data from an API.


   📝 Code Example:
   
      // 1. We mark the function as 'async'
        async function getMyWeather() {
            console.log("Fetching weather..."); // Immediate

            try {
                // 2. The 'await' tells JS: "Go help other customers,  and come back when this data is ready."
                const response = await fetch('https://api.weatherapi.com/v1/current.json');
                const data = await response.json();
                console.log("Weather received:", data.temp); 
            } catch (error) {
                // 3. If the internet is down, we handle it here
                console.log("Could not find weather!", error);
            }
        }

      getMyWeather();
      console.log("I'm not blocked! I can run while the weather is loading.");

================================================================================
                    CHALLENGE: "The Race" 🏁
================================================================================

Here is your challenge. I have mixed Synchronous code (fast), a Promise 
(microtask), and a Timeout (macrotask).

🎯 THE CHALLENGE:
-----------------
Look at the code below and try to determine the exact order of the console.log 
messages.


   📝 Code Example:
   
      console.log("A: Morning alarm goes off!");

      setTimeout(() => {
        console.log("B: Checked social media (10 mins later)");
      }, 0);

      Promise.resolve().then(() => {
        console.log("C: Brushed teeth (Important task)");
      });

      console.log("D: Sat down to work");


💡 HINTS TO HELP YOU:
---------------------

   1️⃣ Sync First: 
      The "Chef" (Call Stack) finishes all immediate tasks first.

   2️⃣ The Priority Lane (Microtasks): 
      Promises have a "VIP" status. Once the Chef is free, they check the 
      Microtask Queue (Promises) before checking the regular Callback Queue 
      (Timeouts).

   3️⃣ The Slow Lane (Macrotasks): 
      setTimeout always goes to the back of the regular queue, even if the 
      timer is 0


✅ EXPECTED OUTPUT ORDER:
-------------------------
   A: Morning alarm goes off!
   D: Sat down to work
   C: Brushed teeth (Important task)
   B: Checked social media (10 mins later)


================================================================================
          THE PRIORITY RULE: Microtasks vs. Macrotasks
================================================================================

In JavaScript, not all "background tasks" are equal. When the Call Stack 
(the Chef) is empty, the Event Loop looks at two different queues:


🔹 1. THE SYNCHRONOUS TASKS (The "Right Now" Lane)
---------------------------------------------------
Anything that isn't wrapped in a Promise or a Timeout runs immediately.

   💡 In our example: 
      A and D. The Chef finishes these before even looking at the queues.


🔹 2. THE MICROTASK QUEUE (The "VIP/High Priority" Lane)
---------------------------------------------------------
This is where Promises (.then, async/await) live.

   ⚡ The Rule: 
      The Event Loop must empty the entire Microtask Queue before it moves 
      on to anything else.

   💡 In our example: 
      C is a Promise. Even if the setTimeout was set to 0, the engine says, 
      "Wait, I have a Promise to finish first!"


🔹 3. THE MACROTASK QUEUE (The "Standard" Lane)
-----------------------------------------------
This is where setTimeout, setInterval, and DOM events live.

   ⏰ The Rule: 
      These tasks only get a turn once the Call Stack and the Microtask 
      Queue are completely empty.

   💡 In our example: 
      B is a Macrotask. It has to wait for the Morning Alarm (A), the 
      Work (D), and the Brushing of Teeth (C) to finish.


🏗️ VISUALIZING THE ENGINE'S DECISIONS
--------------------------------------

   📊 Priority Table:
   
   ┌──────────────┬──────────────┬──────────────────────┬────────────────────────────┐
   │   PRIORITY   │   TASK TYPE  │   EXAMPLE FROM CODE  │           WHY?             │
   ├──────────────┼──────────────┼──────────────────────┼────────────────────────────┤
   │ 1 (Highest)  │ Synchronous  │ console.log("A","D") │ It's on the main thread    │
   │ 2 (Medium)   │ Microtasks   │ Promise.then() (C)   │ Promises are "urgent"      │
   │ 3 (Lowest)   │ Macrotasks   │ setTimeout (B)       │ Timers are "scheduled"     │
   └──────────────┴──────────────┴──────────────────────┴────────────────────────────┘


🌍 WHY DOES THIS MATTER IN THE REAL WORLD?
-------------------------------------------
Imagine you are building a banking app:

   1️⃣ SYNC: 
      You click "Send Money."

   2️⃣ MICROTASK (Promise): 
      The app updates your balance on the screen instantly so you see 
      the change.

   3️⃣ MACROTASK (Timeout/Event): 
      The app sends a "Transaction Successful" notification 2 seconds later.

   ⚠️ IMPORTANT: 
      If the notification (Macrotask) happened before the balance update 
      (Microtask), the user would be very confused!
