🔹 THREE MAIN WAYS TO HANDLE ASYNCHRONOUS TASKS
------------------------------------------------
In JavaScript, some tasks take time (like fetching data from a database). 
We handle them in three main ways:


   A. CALLBACKS (The Old Way)
   ---------------------------
   A callback is just a function passed into another function to be called 
   later.

   📞 Analogy: 
      You leave your phone number at a shop and ask them to "call you back" 
      when a product arrives.

   ❌ The Problem: 
      "Callback Hell" - If you have to do 5 things in a row, your code starts 
      looking like a sideways pyramid (messy and hard to read).



   B. PROMISES (The Better Way)
   -----------------------------
   As discussed above, Promises replaced messy callbacks with a cleaner 
   .then().then() chain. It makes the code look more like a list of 
   instructions.



   C. ASYNC / AWAIT (The Modern Way)
   ----------------------------------
   This is "Syntactic Sugar" - built on top of Promises but makes asynchronous 
   code look and behave like synchronous (line-by-line) code.

   • async: 
     Tells JS that this function will handle asynchronous tasks

   • await: 
     Tells JS to "pause and wait" for the promise to finish before moving to 
     the next line. Much easier to read!

2. ⁡⁢⁣⁣How JavaScript Works Asynchronously⁡
    So, if JavaScript is ⁡⁣⁣⁢synchronous⁡, how does it handle tasks that take time, like fetching data from a server, reading a file, or waiting for a timer, without freezing the entire application?

    - The answer is that JavaScript itself doesn't handle it. The JavaScript Runtime Environment (like a web browser or Node.js) does. 
    - These environments provide features that the JavaScript engine can offload tasks to.

    # ⁡⁣⁢⁣This system works with a few key components:⁡

    - Call Stack: Where your functions are executed, one at a time.

    -  Web APIs / C++ APIs: These are part of the browser (or Node.js environment), not the JavaScript engine. They handle asynchronous tasks in the background (e.g., setTimeout, fetch, DOM events).

    - Callback Queue (or Task Queue): When a background task from a Web API is complete, its callback function is placed in this queue, waiting to be executed.

    - Event Loop: This is the most crucial part. The Event Loop's job is to constantly monitor the Call Stack and the Callback Queue. If the Call Stack is empty, it takes the first function from the Callback Queue and pushes it onto the Call Stack to be executed.

    EX-
        ⁡⁢⁢⁢console.log("Start");⁡

⁡⁢⁢⁢        // setTimeout is a Web API function.
        // We ask it to run our callback function after 2000ms.
        setTimeout(() => {
            console.log("Inside setTimeout after 2 seconds");
        }, 2000);

        console.log("End");

        // Output:
        // Start
        // End
        // Inside setTimeout after 2 seconds

    - A ⁡⁣⁣⁢Promise⁡ is a special JavaScript ⁡⁣⁣⁢object⁡ that acts as a placeholder for a future value

    A Promise can be in one of three states:

       1) Pending: The initial state. The asynchronous operation has not completed yet.
       2) Fulfilled (or Resolved): The operation completed successfully, and the promise now has a resulting value.
       3) Rejected: The operation failed, and the promise has a reason for the failure (an error).

       >< Type of Promise.
           a) Promise.all():
           b) Promise.race():
           c) Promise.allSettled():
           d) Promise.any():
           e) Promise.resolve():
           f) Promise.reject():

      -> A Simple Example: Simulating a Data Fetch
            Let's create a function that simulates fetching user data from a server. This operation takes time, so it's a perfect use case for a Promise. Our function will return a promise that either resolves with user data or rejects with an error.

            ex-

            ⁡⁢⁢⁢function fetchData(api) {
                return new Promise((resolve  , reject ) => {
                    console.log("Fetching data plz wait ");

                    // simulates a network delay of 3 seconds
                    setTimeout(() => {
                        if(api) {
                            // if operation is successfully , we resolve
                            const userData = {
                                name : "John Doe",
                                age : 30
                            }
                            resolve(userData);
                        }
                        else {
                            reject(new Error("Failed to fetch data"));
                        }
                    }, 3000);
                })
            }⁡

  -> ⁡⁢⁢⁣Consuming the Promise⁡
        Now that we have a function that returns a promise, how do we use it? We use the .then() and .catch() methods.

        .then(onFulfilled): Schedules a callback to run when the promise is fulfilled. It receives the resolved value as its argument.

        .catch(onRejected): Schedules a callback to run when the promise is rejected. It receives the error as its argument.


        ⁡⁣⁢⁣Handling a Successful Outcome⁡
            // Let's call our function and tell it to succeed.
          ⁡⁢⁢⁢  const userPromise = fetchUserData(true);

            userPromise
            .then(user => {
                // This block runs only if the promise is FULFILLED.
                console.log("✅ Success!");
                console.log(`User Name: ${user.name}`);
                console.log(`User Email: ${user.email}`);
            })
            .catch(error => {
                // This block runs only if the promise is REJECTED.
                console.error("❌ Error!");
                console.error(error.message);
            });⁡

        /*
            Expected Output:
                Fetching data... please wait.
                (after 2 seconds)
                ✅ Success!
                User Name: John Doe
                User Email: john.doe@example.com
        */

        ⁡⁣⁢⁣Handling a Failure⁡
        
        // Now let's call it and tell it to fail.

        ⁡⁢⁢⁢const failedPromise = fetchUserData(false);

        failedPromise
        .then(user => {
            // This block will be skipped.
            console.log("✅ Success!");
            console.log(`User Name: ${user.name}`);
        })
        .catch(error => {
            // The .catch() block will be executed.
            console.error("❌ Error!");
            console.error(error.message);
        });
⁡
        /*
            Expected Output:
                Fetching data... please wait.
                (after 2 seconds)
                ❌ Error!
                Failed to fetch user data from the server.
        */

    - The function that receives the callback will then execute ("call back") your function at a later time, when a specific task is complete.
